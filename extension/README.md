# 代理开关（Clash / mihomo）0.5.7

这是 **Chromium 浏览器代理配置扩展，不是独立 VPN 客户端**。面向 Chrome、Edge 等支持相应 Manifest V3 扩展 API 的 Chromium 浏览器；Edge 已由用户实测可用，其他浏览器需分别验证，不代表支持所有浏览器。它使用 `chrome.proxy`，不修改系统代理、不建立 TUN、不启动 Clash，也不通过 Clash 控制 API 切换订阅节点。界面中的“代理配置”是协议、主机、端口组合。

## 0.5.7 稳定性修复

- 0.4.x 保存配置时不做校验。升级时，未在使用的无效配置会被移除，并在面板中列出；当前正在使用的无效配置不会被悄悄替换，此时“强制直连”和“释放设置”仍可用，执行后会移除该配置。此前只要有一条无效记录，扩展就无法操作，代理也无法释放。
- Clash 停止后，代理报错改为合并处理，每秒最多记录一次，避免操作队列被占满而拒绝“强制直连”。未显示悬浮窗的标签页不再随每次探测向后台查询状态。
- 流媒体参考检测允许同站地区跳转（如 Netflix `/title/…` 跳到 `/hk-en/title/…`），跳到其他站点仍算失败；连通性探测和出口查询仍禁止跳转。
- 主机里带端口时，提示把端口填到“端口”栏，不再误报“IPv6 地址无效”。
- 强制直连时出口显示“未知”：在中国大陆直连时，`api.ip.sb` 超时，`ipapi.co` 返回人机验证页。新增 `ipinfo.io`（需新增该站点权限）并优先查询，它直连和经代理都能访问；查询失败时显示每个服务的失败原因。
- 线路标识改为 SHA-256 摘要，不再内嵌整段 PAC 脚本；智能分流下每次探测写入存储的数据从约 6.9 KB 降到约 0.4 KB。
- 弹窗页脚版本号改为读取 manifest，不再写死。
- 悬浮窗关闭时，网页内的脚本只读本地存储里的开关，不再给后台发消息，打开网页也不会唤醒 Service Worker。
- 每次探测的后台读取从 6 次存储读取、3 次代理设置读取减到 5 次和 2 次；图标状态不变时不再重写工具栏图标；弹窗和悬浮窗每次探测后只刷新一次状态。

## 安装或升级

1. 保持 Clash/mihomo 运行，确认 HTTP / 混合或 SOCKS5 端口；默认示例为 `127.0.0.1:7897`，请按你的实际配置修改。
2. 如果希望只代理当前浏览器，请自行关闭 Clash 的系统代理和 TUN。扩展不会替你更改这些设置。
3. 在 Chrome 的 `chrome://extensions/` 或 Edge 的 `edge://extensions/` 开启“开发者模式”，选择“加载已解压的扩展程序”，选择包含 `manifest.json` 的 `extension/` 目录。
4. 已加载本项目目录时，更新文件后点击该扩展的“重新加载”，再刷新需要悬浮窗的网页。用 ZIP 安装时先解压，不能把 ZIP 直接当 VSIX 安装。
5. 本版新增 `https://www.gstatic.com/*` 探测权限，浏览器可能要求重新确认或启用扩展。

升级会保留有效的原代理配置。旧版不合法的主机、端口或配置不会被悄悄替换成其他地址，而会报错；如旧存储已损坏，需要在扩展的 Service Worker 调试控制台检查 `chrome.storage.local.get('config')`，备份并修正配置后再试。

## 模式与关闭行为

- **全局代理**：当前浏览器的受支持代理流量使用选定代理服务器，明确的本地/内网地址绕过代理。
- **智能分流**：内网、本地域名以及 `directDomains` 列表命中的域名直连，其余请求使用代理。规则为后缀域名匹配，不是 GeoIP，也不解析域名来猜测是否内网，避免为路由额外做 DNS 查询。
- **强制直连**：显式设置 `mode: direct`，不是简单清除设置。
- **释放设置，跟随系统／其他代理**：清除本扩展的浏览器代理设置；之后的实际路由由系统、策略或其他代理来源决定，不承诺直接联网。

### 代理失败直连回退

0.5.0 默认关闭 PAC 的 `; DIRECT` 后备，并将 PAC 标记为 mandatory，避免 PAC 无效时静默退回默认路由。智能分流下可勾选“代理失败时允许直连”，但会先弹出风险确认。全局模式不使用该 PAC 回退选项。

**禁止后备不等于全系统断网保护。** 智能分流规则命中的域名和内网仍按设计直连；扩展不提供 WebRTC、DNS、QUIC、隐身窗口或浏览器所有协议的无泄漏保证，不应称为 VPN kill switch。

## 状态显示

界面区分：

- 代理已启用但尚未检测；
- HTTP 请求成功；
- HTTP 探测失败／代理报错；
- 设置与实际浏览器代理不一致；
- 被其他扩展或策略接管；
- 强制直连／跟随系统。

浏览器返回的实际代理配置与控制权会参与判断；不再只看保存的 `enabled`。图标 `ON` 仅表示启用了代理配置，不宣称链路持续健康。链路结果超过 7.5 秒会在面板中视为待验证。

## 网络监控

- 测量的是 HTTPS 请求耗时，包含可能的 DNS、TCP、TLS 和服务端时间，**不是 ICMP Ping**。
- 使用可读取状态的 `generate_204` 请求，只把预期 204 视为成功，不再把 opaque/no-cors 响应当作健康证明。
- 弹窗和可见网页悬浮窗按需请求采样；后台将同一路由的并发请求合并，并在 1.5 秒内复用采样，不再每页分别发起探测。
- 最多保存 40 个点。当前探测失败显示 `--`，不会继续展示上一次成功的耗时；波动只计算相邻且都成功的样本，不跨失败点拼接。
- 界面关闭或网页隐藏后不持续主动采样。Service Worker 重启后仍可复用当前路由的短期持久化缓存。
- 模式或代理配置变化后重置历史、出口缓存，进行中的旧线路响应会被丢弃。

HTTP 成功只证明探测请求可完成，不证明所有网站可访问，也不单独证明远端节点身份；允许直连回退时尤其不能据此确认走了代理。

## 配置与失败恢复

- 主机只能填写有效 IP 或 ASCII/Punycode 域名，不接受协议、凭据、路径和 PAC 特殊字符。
- 端口严格限制为 1～65535 的整数，HTTP / SOCKS5 使用白名单。
- 完整覆盖 IPv4 的 `172.16.0.0/12` 私网段，并处理 IPv6 回环、ULA、链路本地和映射私网地址。
- 所有配置写入通过后台串行队列，悬浮窗不再自行读后覆盖整份配置。
- 路由修改先应用浏览器设置并核实，再保存新配置。应用或持久化失败时尝试恢复原设置；回滚失败会明确报错，不伪装成功。
- 这不是跨进程事务。若策略或其他扩展在操作中接管，扩展不会强行覆盖新控制者，需检查实际状态。

## 出口与流媒体参考检测

出口 IP 依次通过 `ipinfo.io` / `api.ip.sb` / `ipapi.co` 获取，前一个失败才查下一个；全部失败时显示各服务的失败原因。按实际路由缓存 30 秒并合并并发请求。查询会向这些服务暴露请求的出口地址；未调用时不进行持续后台查询。

YouTube 只提取页面地区标记，Netflix 只报告两个样本页面的可访问性。**不再输出“完整解锁／仅自制／不支持”的确定判定**，没有执行登录、DRM 或视频播放验证。检测会跟随同站地区跳转；跳转到其他站点、页面改版、网络错误和访问限制都可能导致未知；地区以页面标记为参考，不等于精确物理落地。

## 网页悬浮窗

支持拖动、迷你显示、关闭和点击循环切换“全局 → 分流 → 强制直连”。配置变更统一交给后台处理，网页合成的非可信鼠标事件不会触发代理切换。浮层仍会注入普通网页，需授予对应网站访问权限；浏览器内置页等限制页面无法使用。

## 回归测试和实机检查

在项目根目录运行：

```text
node --test tests/vpn/proxy.test.cjs
```

自动化测试不调用真实 Chrome 代理，不进行外网探测；它不能替代实机验证。

建议装机检查：

1. 将端口填错，确认显示探测失败而不是“已连接”。
2. 正确端口切全局和智能分流，检查出口和状态更新。
3. 在禁止后备的智能分流模式关闭 Clash，访问不命中直连规则的网站，确认不会自动直连；本地和规则内网站仍可直连。
4. 分别尝试“强制直连”和“释放设置”，验证系统代理开启时两者行为不同。
5. 打开多个可见网页和弹窗，在 Service Worker 网络面板确认探测被合并，而不是每页分别发送。
6. 改变模式或代理端口后，旧 IP 和旧采样不应继续显示为当前线路结果。
7. 使用另一个代理扩展接管，确认面板显示不可控或被接管，并检查错误反馈。
8. 刷新网页后测试浮层拖动、迷你模式和点击切换；确认输入无效端口能看到明确错误。
